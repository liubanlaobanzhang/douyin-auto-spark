# 2026-08-26

## 修正：失败截图附带微信推送（douyin-auto-spark）

用户要求：出错时自动保存的截图要附到微信（Server酱）推送里，并考虑用仓库本身作图床。

实现（改 `.github/workflows/renew-fire.yml` + README）：
- job 增加 `permissions: contents: write`（GITHUB_TOKEN 推分支所需）。
- 新增步骤「上传失败截图到仓库图床」，条件 `failure() && env.FTQQ_SENDKEY != ''`：
  - 把 `artifacts/*.png` 提交到独立 `screenshots` 分支（不存在则 `git switch --orphan` 创建），路径 `screenshots/<YYYY-MM-DD>/run-<run_id>/`。
  - 只保留最近 14 天截图（按日期目录 `git rm`），防止仓库膨胀。
  - 用 python3 生成 Markdown（raw.githubusercontent.com 主链 + jsDelivr 备用链，中文文件名 urllib.parse.quote 编码），经 GITHUB_ENV 多行 heredoc 语法写入 `SCREENSHOT_MARKDOWN`。
- 「发送构建失败通知」步骤：desp 末尾追加 `### 失败现场截图` + SCREENSHOT_MARKDOWN。
- README：Secrets 表补 FTQQ_SENDKEY 行，新增微信推送截图说明段落。

本地验证（Git Bash 模拟 bare origin）：4 场景全过——首次建孤儿分支、已有分支 fetch 累积+过期清理（删 08-01 留 08-20/08-26）、无截图时写空 SCREENSHOT_MARKDOWN 优雅跳过、重跑同 run_id 同内容不产生空提交。YAML 用 pyyaml 解析校验，workflow 内嵌脚本与测试脚本逐字一致，通知步骤 python 经 ast.parse 校验。

注意：GITHUB_TOKEN 推送不会触发其他 workflow（GitHub 防递归机制）；`scrreenshots/`（拼写错误的空目录）与本次改动无关，未动。
