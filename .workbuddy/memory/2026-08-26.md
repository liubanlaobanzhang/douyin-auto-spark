用户要求：出错时自动保存的截图要附到微信（Server酱）推送里，并考虑用仓库本身作图床。

实现（改 `.github/workflows/renew-fire.yml` + README）：

- 新增步骤「上传失败截图到仓库图床」，条件 `failure() && env.FTQQ_SENDKEY != ''`：
  - 把 `artifacts/*.png` 提交到独立 `screenshots` 分支（不存在则 `git switch --orphan` 创建），路径 `screenshots/<YYYY-MM-DD>/run-<run_id>/`。
  - 只保留最近 14 天截图（按日期目录 `git rm`），防止仓库膨胀。
  - 用 python3 生成 Markdown（raw.githubusercontent.com 主链 + jsDelivr 备用链，中文文件名 urllib.parse.quote 编码），经 GITHUB_ENV 多行 heredoc 语法写入 `SCREENSHOT_MARKDOWN`。
- 「发送构建失败通知」步骤：desp 末尾追加 `### 失败现场截图` + SCREENSHOT_MARKDOWN。
- README：Secrets 表补 FTQQ_SENDKEY 行，新增微信推送截图说明段落。

本地验证（Git Bash 模拟 bare origin）：4 场景全过——首次建孤儿分支、已有分支 fetch 累积+过期清理（删 08-01 留 08-20/08-26）、无截图时写空 SCREENSHOT_MARKDOWN 优雅跳过、重跑同 run_id 同内容不产生空提交。YAML 用 pyyaml 解析校验，workflow 内嵌脚本与测试脚本逐字一致，通知步骤 python 经 ast.parse 校验。

注意：GITHUB_TOKEN 推送不会触发其他 workflow（GitHub 防递归机制）；`scrreenshots/`（拼写错误的空目录）与本次改动无关，未动。

## 修正2：上传步骤在 CI 报 `set: Illegal option -o pipefail`

`mcr.microsoft.com/playwright:v1.61.0-jammy` 新版镜像**精简掉了 bash**，容器 job 里 `run:` 步骤默认落到 `/bin/sh`（dash）。原上传步骤的 `set -euo pipefail`、`shopt -s nullglob`、数组、`[[ ]]` 全是 bash 专属语法，第一步就崩（exit 2）。

修复：整个上传步骤重写为**纯 POSIX sh**：
- `set -eu`（去掉 pipefail）；数组 → `for + [ -f ]` 循环判断；`[[ regex ]]` → `case [0-9]...` 模式匹配；空 glob 用 `[ -f ] || continue` 兜底。
- 本地用**真实 dash**（Git Bash 自带 /usr/bin/dash）复测 4 场景全过；`sh -n`/`bash --posix -n` 语法通过；YAML 仍可用 pyyaml 解析。

教训：给 Actions 容器 job 写脚本前，先确认镜像是否带 bash；Playwright 官方镜像已移除 bash，一律按 POSIX sh 写。

## 修正3：放弃本地 git，改用 GitHub REST API 上传截图 + 手动触发跳过微信通知

用户报错 `fatal: not in a git directory`（上传步骤的 `git config` 找不到仓库）——container job 里 checkout 的 git 状态不可靠，git 方案彻底放弃。

新方案（全部在 `.github/workflows/renew-fire.yml`）：
- 上传步骤改为**纯 Python + GitHub REST API**（`urllib.request`，GITHUB_TOKEN 认证，`GITHUB_API_URL` 可配置）：
  - 分支不存在时 `GET /repos/{repo}` → `GET /git/ref/heads/{default}` → `POST /git/refs` 基于默认分支创建 `screenshots` 分支；
  - `PUT /repos/{repo}/contents/screenshots/{name}` 上传，**扁平命名** `YYYY-MM-DD-run-{run_id}-{原文件名}`（中文名经 quote 编码）；
  - 清理：`GET /contents/screenshots` 列出全部文件，解析文件名前 10 位日期，超 14 天 `DELETE /contents/{path}`；
  - 生成 raw + jsDelivr Markdown 写入 `SCREENSHOT_MARKDOWN`（GITHUB_ENV 多行 heredoc 语法）。
- 成功/失败微信通知步骤 `if` 增加 `env.EVENT_NAME != 'workflow_dispatch'`：**手动触发跳过微信通知**（测试不打扰），邮件照发。
- 注意：Contents API 不能删目录，必须扁平文件结构（三层目录方案在真实 API 下会失败，mock 测试发现）。

验证：本地 mock GitHub API 服务器（http.server 模拟 branches/refs/contents 端点）集成测试 3 场景全过：首次建分支+双截图上传+URL 编码、已有分支+过期清理（删 08-01 留 08-20）、无截图优雅跳过。YAML pyyaml 解析 + heredoc 内 Python ast.parse 校验通过。测试环境坑：子进程建 socket 被沙箱拦（WinError 10106），需同进程 exec；venv python 的 SSL 初始化坏，用系统 python 跑测试。
